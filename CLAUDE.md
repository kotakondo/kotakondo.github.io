# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Kota Kondo's personal academic website (MIT AeroAstro / Aerospace Controls Lab), built on a fork of the
[al-folio](https://github.com/alshedivat/al-folio) Jekyll theme and served at https://kotakondo.github.io.
`README.md` is upstream al-folio's documentation (41 KB) — it is the reference for stock theme features, not
a description of this site.

Almost all routine work is **content editing in data files**, not template work: Markdown collections,
`papers.bib`, and YAML under `_data/`. Only reach for `_layouts/`/`_includes/`/`_sass/` when the change is
genuinely presentational.

## Commands

Ruby is present on this machine but `bundle`/`jekyll` are **not installed**, so Docker is the only local path:

```bash
docker compose up          # http://localhost:8080, --watch + livereload (bin/entry_point.sh)
                           # first run pulls a ~400MB image; restarts Jekyll on _config.yml changes
docker compose up --build  # rebuild the image locally instead of pulling
```

**`amirpourmand/al-folio:latest` is currently broken** (verified 2026-07-31): the image ships Ruby 4.0,
which dropped `ostruct` as a default gem, so `jekyll-twitter-plugin` fails to load with
`cannot load such file -- ostruct (LoadError)`. CI is unaffected — it pins Ruby 3.2.2, where that gem is
still bundled. To build locally without modifying the repo, copy the mounted source inside the container
and add the removed default gems there:

```bash
docker compose run --rm --entrypoint="" jekyll bash -lc '
  cp -a /srv/jekyll /tmp/site && cd /tmp/site && rm -f Gemfile.lock
  printf "\ngem \"ostruct\"\ngem \"csv\"\ngem \"base64\"\ngem \"bigdecimal\"\ngem \"logger\"\ngem \"observer\"\ngem \"drb\"\n" >> Gemfile
  bundle install --quiet && bundle exec jekyll build --lsi --destination /tmp/out'
```

Adding those gems to the repo's `Gemfile` would fix it permanently, but that has not been done.

Native (needs `bundle install` + `pip install jupyter` first):

```bash
bundle exec jekyll serve --lsi
bundle exec jekyll build --lsi   # == bin/cibuild; output in _site/
purgecss -c purgecss.config.js   # strips unused CSS from _site/assets/css (CI does this after build)
```

There is no test suite and no linter. `.pre-commit-config.yaml` configures whitespace/EOF/YAML/large-file
hooks (`pre-commit run --all-files` if installed) — note the repo already contains multi-MB GIFs, so the
large-file hook is not being enforced in practice.

## Deployment

Push to `master` → `.github/workflows/deploy.yml` builds with `JEKYLL_ENV=production` and publishes `_site`
to the `gh-pages` branch (which is the Pages source). Pull requests build but do not deploy. There is no
manual deploy step, and `_site/` is gitignored — never commit build output.

The other three workflows are upstream artifacts that publish al-folio Docker images; they are gated on
`github.repository_owner == 'alshedivat'` (or need `DOCKER_*` secrets) and do nothing here.

Since the deploy job is the only build that runs, a malformed `_config.yml` or Liquid error only shows up as
a failed Actions run (this has happened before — commit `e7e91a0`). Preview locally with Docker before
pushing config or template changes.

## Content model

| To change | Edit |
| --- | --- |
| Homepage bio, profile photo, which sections appear | `_pages/about.md` front matter + body |
| Publications | `_bibliography/papers.bib` |
| Project cards | `_projects/*.md` |
| News/announcements on homepage | `_news/*.md` |
| CV page | `_data/cv.yml` (+ `assets/pdf/` for the linked PDF) |
| Co-author links, venue badges, repo lists | `_data/coauthors.yml`, `_data/venues.yml`, `_data/repositories.yml` |
| Site-wide switches, social handles, plugin config | `_config.yml` |

**Publications** are generated by jekyll-scholar from `papers.bib`. Per-entry custom fields become buttons
via `_layouts/bib.html`: `arxiv`, `code`, `video`, `pdf`, `html`, `website`, `poster`, `slides`, `abstract`,
`abbr`, `preview`, `selected`. `selected={true}` also surfaces the paper on the homepage.
`filtered_bibtex_keywords` in `_config.yml` + `_plugins/hideCustomBibtex.rb` strip these from the displayed
BibTeX. Author names must be written `Kondo, K.` style to match `scholar.last_name: [Kondo]` /
`first_name: [Kota, K.]` and get underlined; co-authors are auto-linked from `_data/coauthors.yml`, keyed by
last name with a list of accepted first-name spellings.

**Projects** (`_projects/*.md`) use `importance` (ascending sort), `category` (must match an entry in
`display_categories` in `_pages/projects.md` — currently only `research`), `selected: true` (homepage),
`img:` (site-root-relative path), and `related_publications:` (bib keys).

**News** (`_news/*.md`) sort by the `date` field, not filename; `inline: true` renders the body directly in
the homepage table. Homepage shows the newest `announcements.limit` (10) items in a scroll box (`max-height: 60vw`); the full list is at `/news/`.

**CV**: `_layouts/cv.html` renders `_data/cv.yml` only when `_data/resume.json` does **not** exist — the
JSON Resume file was deliberately deleted (commit `0eec19f`). Re-adding any `_data/resume.*` silently
switches the page to the resume renderer and `cv.yml` stops showing. Each `cv.yml` entry's `type:` must be
one of `map`, `time_table`, `list`, `nested_list`, `list_groups`, matching `_includes/cv/*.html`.

**Navigation** comes from `nav:`/`nav_order:` in `_pages/*.md` (publications 1, projects 2, cv 4;
`/repositories/` is `nav: false` but still built). The blog is effectively disabled — `blog_nav_title` is
blank and there is no `_posts/` directory — though `blog/index.html` and the archive layouts remain.

## Gotchas

- **Adding a paper in a new year requires editing `_pages/publications.md`.** Its `years:` front-matter list
  is hardcoded; an entry whose year is missing from that list renders nowhere.
- **Publication preview images live in `assets/img/publication_preview/`**, while project `img:` paths point
  at `assets/img/`. A GIF used by both a paper and its project card must be copied into both directories.
- **GIFs bypass responsive images.** `jekyll-imagemagick` pre-generates 480/800/1400px WebP variants for
  jpg/jpeg/png in `assets/img/` only; `_includes/figure.html` carries a local patch skipping the `<source
  srcset>` block for `.gif` so the browser doesn't request non-existent `.gif-480.webp`. Do not revert it.
- **The accent color is `$purple-color` in `_sass/_variables.scss`** — the variable name is upstream legacy,
  its value is green (`#0ac44b`). It feeds `--global-theme-color` in light mode; dark mode uses
  `$cyan-color`. Change both to fully re-theme.
- **The favicon is the `icon:` emoji in `_config.yml`** (currently ✈️), not a file.
- `_plugins/external-posts.rb` fetches `external_sources` RSS (still pointing at al-folio's Medium feed) on
  every build — a network call and phantom posts. Clearing `external_sources` removes it.
- If `bibtex_show={true}` is ever added to an entry, also add `video` to `filtered_bibtex_keywords`; the
  `video` field is a local addition and is not currently filtered out of the BibTeX popup.

## Local deviations from upstream al-folio

Keep this list in mind when syncing/rebasing on upstream — these files will conflict and their changes are
intentional:

- `_sass/_variables.scss` — theme color; `_sass/_cv.scss` — CV date badges use the theme color instead of
  MDB dark red; `_sass/_base.scss` + `assets/js/masonry.js` — `fitWidth: true` and `.grid { margin: 0 auto }`
  to center the project grid.
- `_includes/figure.html` — GIF srcset skip (see above).
- `_layouts/bib.html` — adds the `Video` button.
- `_includes/news.html` — dates render as `%b %Y` (month + year) instead of full dates.
- `_includes/header.html`, `_includes/social.html`, `_layouts/about.html` — bolded full name in the navbar,
  email icon removed, homepage section arrangement.
- `_includes/selected_projects.html` — local addition with no upstream counterpart; driven by
  `selected_projects: true` in `_pages/about.md`.
